Unauthenticated deserialization in the XML-RPC endpoint (releases before 6.1.5)

CVE-2026-129448 [CVE] [CVE json] [OSV json]

Last updated: 2026-11-17T11:03:46.637Z

Affected

  • Apache Roller from 4.0.0 before 6.1.5

Description

Deserialization of Untrusted Data in Apache Roller versions 4.0.0 through 6.1.4 allows an unauthenticated remote attacker to execute arbitrary code. The XML-RPC endpoint accepts vendor extension types and deserializes them before authenticating the requester.

This is the same vulnerability as CVE-2026-82384, which listed only Apache Roller 6.1.5 as affected. This issue is being actively exploited.

Users are recommended to upgrade to Apache Roller 6.1.6 or later, which disables the extension types and rejects XML-RPC requests when the XML-RPC feature is disabled.

Users who cannot upgrade right away should set “enabledForExtensions” to “false” in WEB-INF/web.xml, or remove the “/roller-services/xmlrpc” servlet mapping, and restart Roller. Disabling XML-RPC in the administration UI is not enough, because older versions deserialize the request before checking that setting.

Deserialization of untrusted data in weblog update ping responses

CVE-2026-123374 [CVE] [CVE json] [OSV json]

Last updated: 2026-11-11T12:41:34.662Z

Affected

  • Apache Roller from 4.0 through 6.1.6

Description

Deserialization of Untrusted Data vulnerability in Apache Roller. When Roller sends a weblog update ping, its XML-RPC client deserializes Java object data contained in the ping target's response, so a party that controls that response can run code in the Roller server process. This issue affects Apache Roller from 4.0 through 6.1.6. Users are recommended to upgrade to version 6.1.7, which removes the unsafe deserialization.

CVE-2026-111824 [CVE] [CVE json] [OSV json]

Last updated: 2026-11-11T12:39:21.554Z

Affected

Improper Neutralization of Input During Web Page Generation ('Cross-site Scripting') in Apache Roller 6.1.6 allows an authenticated user with the Author role on a weblog that uses a custom theme to store script that runs in the browser of anyone who opens the file's resource URL. Cross-site request forgery in Planet administration lets an attacker make the server fetch arbitrary URLs

CVE-2026-105154 [CVE] [CVE json] [OSV json]

Last updated: 2026-11-11T12:38:52.947Z

Affected

  • Apache Roller from 4.0 through 6.1.6

Description

Cross-Site Request Forgery (CSRF) in the Planet feed aggregator administration of Apache Roller 4.0 through 6.1.6 allows an unauthenticated attacker to make the Roller server fetch a URL the attacker chooses, including internal addresses, by inducing a logged-in global administrator to open a crafted web page. The action that adds a Planet subscription can be triggered cross-site; in recent releases it accepts GET requests, which Roller's CSRF token check does not cover. The action fetches the supplied URL and saves the subscription, and any fetched content that parses as a feed is then published without authentication in the aggregated Planet feed. The Planet aggregator is enabled by default. Users are recommended to upgrade to Apache Roller 6.1.7 or later, which requires POST requests with a valid CSRF token for Planet administration changes and turns the Planet aggregator off by default.

XML external entity processing in AtomPub entry parsing

CVE-2026-105153 [CVE] [CVE json] [OSV json]

Last updated: 2026-11-11T12:38:35.207Z

Affected

  • Apache Roller from 4.0 through 6.1.6

Description

Improper Restriction of XML External Entity Reference in Apache Roller 4.0 through 6.1.6 allows an authenticated user with no weblog permissions to read files readable by the Roller process and cause the server to issue outbound HTTP requests to attacker-chosen destinations, by submitting a crafted Atom entry to the AtomPub endpoint. The entry body is parsed with a parser configuration that permits external parameter entities and external DTD subsets, and the parse happens before any per-weblog authorization check and before any check of whether the AtomPub feature is enabled, so the endpoint is reachable by any authenticated account on a default installation. Users are recommended to upgrade to Apache Roller 6.1.7 or later, which parses AtomPub entries with a hardened XML configuration and rejects AtomPub requests while the feature is disabled.

Insufficient Session Expiration on Password Change

CVE-2025-24859 [CVE] [CVE json] [OSV json]

Last updated: 2025-04-18T15:26:03.795Z

Affected

  • Apache Roller from 1.0.0 before 6.1.5

Description

A session management vulnerability exists in Apache Roller before version 6.1.5 where active user sessions are not properly invalidated after password changes. When a user's password is changed, either by the user themselves or by an administrator, existing sessions remain active and usable. This allows continued access to the application through old sessions even after password changes, potentially enabling unauthorized access if credentials were compromised.

This issue affects Apache Roller versions up to and including 6.1.4.


The vulnerability is fixed in Apache Roller 6.1.5 by implementing centralized session management that properly invalidates all active sessions when passwords are changed or users are disabled.
